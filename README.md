# Mizuyori

Локальное веб-приложение: запускается на вашем компьютере и открывается в браузере.

## Запуск

Двойной клик по `Mizuyori.bat`. Браузер откроется сам.

## Главная

| Где | Что |
|---|---|
| слева | часы, календарь (клик по месяцу — вернуться к сегодняшнему дню) |
| по центру | чат: Enter — отправить, Shift+Enter — новая строка |

**Чат.** Ответы ИИ с разметкой — жирный, курсив, списки, заголовки, код с кнопкой «Копировать», таблицы;
звёздочек `**` на экране нет. Ответ печатается плавно, целыми словами, новые сообщения мягко появляются.
Под ответом: **➕ В задачи** (пункты списка из ответа или выделенный текст — галочки, срок, список),
**🎯 В цель** (название из заголовка или выделения, можно сразу с шагами-задачами), **✎ В заметку**, **⧉ Копировать**.

Клик по дню в календаре открывает экран «Дела» с задачами на этот день.

**Агенты** — справа от чата, сверху вниз по ходу работы, по группам (Общение, Память, Дела и цели, Душа; группы сворачиваются): Собеседник → Память → Смысл → Летописец → Стратег → Душа. У каждого — состояние и последний результат.
Когда один берётся за дело после другого, по дорожке между ними летит искра; закончил — вспышка
(зелёная — успех, красная — ошибка). Кольцо крутится, пока агент работает, дуга — сколько раз за сегодня,
звёздочки — уровень.

- **Клик по агенту** — окно: уровень и опыт, **история решений** (что сделал, почему, результат, поиск),
  **своя память** (правила и приёмы — пишете вы, они добавляются к заданию агента; частые ошибки — собирает сам),
  **записки** этому агенту.
- **Опыт** растёт от полезных действий (новые факты, связи, привязки, мнения): уровни на 10, 30, 70, 150 опыта.
- **Доска** — записки агентов друг другу: Память пишет Стратегу и Душе о новой цели — Стратег сам раскладывает
  задачи, Душа обновляет мнения. Можно написать агенту и самому.

## Дела

Отдельный экран в меню. Вверху — кольцо «сколько сделано на сегодня» и виды:

| Вид | Что |
|---|---|
| Список | задачи по группам и заметки |
| Доска | колонки «Просрочено», «Сегодня», «Завтра», «На неделе», «Позже», «Без срока», «Выполнено»; перетащите карточку — срок поменяется сам, «+» в колонке — быстрая задача |
| Неделя | семь дней, перетаскивание между днями, стрелки — соседние недели; в ⚙ выбираются первый день недели и рабочие дни |
| Цели | карточки целей с кольцом прогресса, шагами-задачами, «+ шаг», «Цель достигнута», новая цель; «Разложить по целям (ИИ)» |
| Заметки | заметки |

Клик по карточке — окно правки: текст, срок (быстрые кнопки «Сегодня», «Завтра», «Выходные»), список, цель, выполнено, удалить.

- **Задачи:** у задачи могут быть срок, список, приоритет и повторение (каждый день, по рабочим дням, каждую неделю или месяц).
  При завершении повторяющейся задачи следующий экземпляр создаётся автоматически. Срочные и важные задачи показываются выше.
- **Входящие:** отдельное место для ещё не разобранных задач. После назначения срока, списка или цели задача сама покидает «Входящие».
- **Архив и корзина:** выполненные задачи можно одним действием перенести в архив и вернуть обратно. Обычное удаление отправляет задачу
  в корзину, где её можно восстановить или удалить навсегда.
  Галочка — выполнено, клик по задаче — изменить, крестик — переместить в корзину.
- **Списки задач:** «Дом», «Работа», «Покупки» и свои — с цветом и значком. Фишки над задачами фильтруют по списку, кнопка справа от них — настроить списки.
- **Календарь и задачи:** точка под числом — на этот день есть задачи. Клик по дню показывает задачи на этот день, новая задача получает эту дату. Повторный клик — снова все дни.
- **Заметки:** первая строка — заголовок; Ctrl+Enter — сохранить, Esc — закрыть.
- **ИИ в чате** — через cloud.ru (Evolution Foundation Models), ответ печатается по мере генерации.

## Работа

Раздел в меню для отдела: слева разделы, справа таблица. Клик по строке — правка, «+» — новая запись,
«⬇ Excel» — выгрузка любого списка.

| Раздел | Что |
|---|---|
| Сотрудники | ФИО, должность, табельный №, телефон; закрепляется **топливная карта** и **автомобиль** |
| Автомобили | марка, модель, госномер, топливо, расход лето / зима (л/100 км), ОСАГО и техосмотр до, ТО (каждые N км, пробег и дата последнего), шины, водитель. **Напоминания** сверху: ОСАГО, техосмотр — за 30, 14 и 3 дня и после срока; ТО по пробегу из путевых («до ТО 1 500 км»); смена шин к сезону. Клик по машине — **история по месяцам** с графиком: пробег, норма, факт, заправки, остаток |
| ГСМ | загрузка **выписки по топливным картам** (.xls/.xlsx, как у поставщика: «Карта № …», «Отгрузка / Возврат»); свод по картам — водитель, авто, литры по видам топлива, сумма, операции; клик — все заправки карты; повторная загрузка не задваивает |
| ГСМ → Статистика и контроль | за любой период: километраж и топливо по машинам (₽ за км, расход факт/норма, «реальная норма» по методу наименьших квадратов), **признаки для проверки** (перерасход, заправка больше бака, заправки в отпуске/на больничном, не то топливо, невозможный маршрут, две заправки подряд, ночью, в выходные, выбивается из парка) с оценкой в литрах и рублях, кто и как заправляется, любимые АЗС, цены, часы и дни недели, рекорды. Это признаки, а не доказательство |
| ГСМ → Анализ движения ГСМ | остаток на начало + заправлено − расход = остаток на конец. Период — быстрые кнопки (этот/прошлый месяц, квартал, с начала года, всё время) и сетка месяцев (Shift+клик или «Несколько месяцев» — период). Сверху итоговые карточки и баланс топлива, ниже карточка на каждую машину: спидометр, топливо, расход по норме и факту, полоска «норма — факт», статус перерасход/экономия. Остаток на конец из последней путевой — по нему считается факт; не вписан — по норме. За период — сводка по месяцам, где есть путевые. Excel — все числа значениями (остатки видны везде), за период — итоговый лист и лист на каждый месяц |
| Топливные карты | номер, поставщик, лимит; карты из выписки добавляются сами — останется закрепить за сотрудником |
| Табель | месяц × сотрудники, коды Я, В, ОТ, Б, К, ДО, НН, РВ и часы; **норма месяца** (дни и часы); «Заполнить пустые» — по **производственному календарю** (праздники, переносы, рабочие субботы, сокращённые дни по 7 ч); **«+ Отпуск / больничный / командировка»** — период с датами, табель заполняется сам (праздники в отпуск не входят), убрать период — вернётся обычный график |
| Служебные записки | номер (по порядку за год), дата, кому, от кого, тема, текст, статус; **печать** готовым бланком |
| Договоры | №, дата, контрагент, ИНН, предмет, сумма, срок действия (⚠ за 30 дней до конца), статус |
| Счёт-оферты | договор и счёт в одном: №, поставщик, за что, сумма, оплатить до (⚠ просрочено), оплачено |

**Производственный календарь** зашит на 2026 и 2027 год (постановления Правительства РФ № 1466 от 24.09.2025 и № 1187
от 17.09.2026). Хранятся текущий и следующий год: когда наступит 2027-й, календарь 2026 года удалится сам.

**Сезоны** для норм — по датам (по умолчанию зима с 01.11 по 31.03, меняется кнопкой «изменить» в путевых листах).
Если граница внутри месяца, норма считается частями по дням («зима 16 дн. + лето 14 дн.»). Начало месяца
(км и остаток) подставляется само из конца прошлого.

**Округление остатка** — как пишут водители: по умолчанию целыми литрами (42,26 → 42), можно до 0,1 л или без
округления (выбор в строке над таблицей). Если факт не записан, он считается из округлённого остатка — сходится с бумагой.

**Анализ движения ГСМ:** пробег = км конец − км начало; по норме = пробег × норма (лето/зима из карточки автомобиля) / 100;
остаток на конец вписан из последней путевой → факт = остаток на начало + заправлено − остаток на конец; не вписан — факт равен норме, а остаток считается сам;
отклонение = факт − норма. Выгрузка в Excel — с формулами,
можно поправить цифры прямо в Excel.

**Выгрузка ГСМ в Excel** — три листа: «Свод» (карта, водитель, должность, автомобиль, госномер, литры по видам
топлива, всего, сумма, операций, итоги формулами), «Выписка» (как у поставщика, но с водителем и авто у каждой карты),
«По видам топлива». **Табель в Excel** — сетка месяца с днями недели, выходные подсвечены, итоги дней и часов.

### Агенты Работы

Девять помощников отдела главного механика стоят на главной в группе «Работа» (и на графе «Мозги»).

| Агент | Что делает |
|---|---|
| Старший инженер | сводит срочные записки других агентов; **пишет служебные записки** (тема → черновик в «Служебных записках», с ИИ или по шаблону) |
| Механик по выпуску | ТО, страховка, шины: какая машина готова к выпуску |
| Диспетчер по выпуску | кто сегодня выходит (табель, отпуск, больничный) и на какой машине; сколько машин готово |
| Трассировщик | подозрительные заправки, карты без машины, странности расхода и пробега |
| Кадровик | табель за месяц, ближайшие отпуска, пустые табельные номера и должности |
| Юрист | сроки договоров и оплата счёт-оферт |
| Водитель автомобиля | напоминания водителям: ТО, ОСАГО, техосмотр, шины |
| Экономист | цена литра к прошлому месяцу, деньги на заправках и перерасходе под вопросом, просроченные и ближайшие оплаты |
| Делопроизводитель | старые черновики записок, повторяющиеся номера, договоры без номера, даты, предмета |

У каждого своя память (правила и приёмы пишете вы; частые замечания копятся сами со счётчиком), история решений,
опыт и уровень. Развиваются в фоне: раз в 3 часа обходят данные (срочное уходит записками на доску), раз в сутки при
подключённом ИИ каждый записывает себе новый приём из своих частых замечаний. **В чате:** можно обратиться к агенту по имени — «Механик, что по ТО?», «Юрист, что с офертами?» — он отвечает в своей
роли со своими правилами и замечаниями. «Старший инженер, напиши служебную записку про …» создаёт черновик в «Служебных
записках». Если разговор про работу (машины, табель, договоры, заправки), замечания агентов подмешиваются в ответ сами.
**В «Мозгах»:** все семь на внешнем кольце агентов, с нитями к разделам и подсветкой, пока работают.
Код: `mizuyori/work_agents.py`, окно агента — `static/agents.js`.

### Постоянная учёба агентов

Агенты думают по событиям (`learning.py`): поправили в чате («нет, не так…»), пришёл урок от коллеги или накопились новые ошибки (обзор раз в 4 часа). Из поправки рождается приём в памяти агента («по вашей поправке»); полезным опытом агент делится с коллегой запиской «Урок: …» на доске, а получатель сам решает, принять ли её в память («урок от …»). Чему агент научился за неделю — в его карточке, вкладка «Память». Предохранители: агенты думают по одному, пока идёт чат — фон ждёт, не больше `запросов_в_час` обращений к ИИ (config.json → `агенты`, по умолчанию 12); кнопка «Выключить» в карточке отключает фоновую учёбу.

Справка с цифрами (`reference.py`): на вопросы вроде «сколько литров залил Иванов за октябрь?», «сколько проехала Камри?», «какие машины без ОСАГО?» агенты (Экономист, Механик) получают точные числа из базы — те же, что на странице «ГСМ → Путевые» — и пересказывают их, а не придумывают. Ревизия учёбы: в карточке агента, вкладка «Память» → «Проверить, чему научились» — список приёмов, которые агенты записали сами, с пометками «слишком общее» и «повторяет другой»; «Оставить» делает приём правилом, «×» удаляет.

### Поиск в интернете («ноги»)

Снабженец (и Склад, Юрист, Бухгалтер, Экономист) ходит в сеть по просьбе в чате. Понимает: «Снабженец, найди цену на шины»,
«Снабженец найди …» (запятая не нужна), «поищи в интернете …», «подбери аналоги …», «посмотри в сети сколько стоит …»,
«сравни цены на …»; а Снабженцу достаточно назвать нужное: «цены на шины Хайлюкс?», «где купить масляный фильтр».
**Закупка техники.** Если речь про запчасти, масла, шины, фильтры или артикул (например «фильтр vic c111»), Снабженец и Склад
ищут умнее: уточняют запрос («автозапчасти артикул», чтобы не нашлись фильтры для воды), исправляют русскую «с» в артикуле,
пробуют написания «C111» / «C-111», отдельно идут по магазинам запчастей (Exist, Emex, Autodoc, ZZap, Autopiter, Фарпост, Drom;
для шин — 4tochki, Колёса-Даром), а при подключённом ИИ добавляют 1–2 формулировки от модели. **Приоритет — Приморский край:** Снабженец и Склад ищут отдельным запросом с «Владивосток Приморский край», а в выдаче местные
предложения (Владивосток, Уссурийск, Находка, Артём и др. в названии, описании или адресе) идут выше всех и помечены 📍 Приморье.
Выдача склеивается без повторов
и сортируется: магазин запчастей и точный артикул выше, Википедия и «ответы» ниже; цена из сниппета выделяется (**1 250 ₽**).
Вопросы про свои данные («какие цены у нас по договору…», «проверь договор…») в интернет не уходят.
Ищет через DuckDuckGo, а если он недоступен или просит капчу — через Bing; ключей не нужно. Если не ответил ни один — честно
пишет, что сети нет. **Если интернет не помог (оба поисковика недоступны или ничего не нашлось) и ИИ cloud.ru подключён,
Снабженец отвечает по вашему ключу из знаний модели**: ориентиры, на что смотреть, какие бывают аналоги. В сообщении прямо
сказано, что это не свежие данные: ссылок и точных цен модель не выдумывает, их надо проверить у поставщика. Код: `mizuyori/senses.py`, тесты: `tests/test_senses.py`.

### Смета на ремонт в чате

Скрепка в чате: прикрепите смету (PDF с текстом, Excel `.xlsx`/`.xls`, Word `.docx`, текст) — Старший инженер разбирает её в структуру (объект, исполнитель, заказчик, номер, дата, работы и материалы с суммами, НДС, итого) и присылает в чат, что он понял. Арифметика проверяется кодом, а не ИИ: расхождения «кол-во × цена ≠ сумма» и «сумма позиций ≠ итог» выводятся в блоке «Проверьте». Дальше словами: «подтверждаю смету», «отклони смету» или поправка («в смете исполнитель ООО Ромашка», «итого 125 000»). Файлы лежат в `data/вложения/`, разобранные сметы — в таблице `раб_сметы`. Сканы и фото (PDF без текста, JPG/PNG) читаются, если в настройках ИИ выбрана «Модель для сканов и фото» (`ии.модель_зрения`) — модель, которая видит картинки; без неё агент попросит PDF с текстом, Excel или Word. Читаются до 6 страниц; распознанное по сканам стоит проверять особенно внимательно. 

**Документы по смете.** После «подтверждаю смету» работает цепочка агентов: Делопроизводитель подбирает бланки и сообщает коллегам на доске, Старший инженер пишет служебную записку (она же попадает в «Служебные записки» как черновик), Механик — дефектовую ведомость, Юрист — договор (сумма не меньше `договор_от_рублей` в `config.json` → `агенты`, по умолчанию 100 000 ₽) или счёт-оферту (меньше). Всё приходит в чат ссылками на Word-файлы (`data/документы/`) и является черновиком: чего нет в смете, помечено «[не указано]» или «[заполнить]». Свои образцы кладите в `шаблоны/документы/` (`служебная_записка.docx`, `дефектовая_ведомость.docx`, `договор.docx`, `счёт_оферта.docx`) с метками `{{объект}}`, `{{исполнитель}}`, `{{итого}}`, `{{таблица}}` и др. — описание в `шаблоны/документы/README.txt`; агенты заполнят их вместо встроенных.

### Путевые листы из чата

В чате: «оформи путевой на Иванова Прадо» (или «заполни», «подготовь», «сделай»; можно «на завтра») — **Диспетчер по выпуску** берёт бланк из `шаблоны/путевые/`, подставляет из базы машину, госномер, ФИО водителя и номер его водительского удостоверения (карточка сотрудника → «Водительское удостоверение №») и дату выдачи, и кладёт готовый Excel прямо в чат ссылкой (лицевая сторона и оборот — на двух листах файла; файлы лежат в `data/путевые_готовые/`). Если по фамилии подходит несколько бланков (у водителя несколько машин), агент перечислит их — добавьте марку машины или слово «все». Водитель и машина ищутся в базе по бланку (госномер, марка), так что одного шаблона на каждую пару достаточно; чего нет в базе — остаётся из шаблона, с предупреждением в ответе.

На принтер файл уходит, только если попросить: «распечатай путевой…». Печать идёт через установленный Excel (Windows), двусторонняя; принтер и режим — `config.json`, раздел `печать`: `принтер` (пусто — по умолчанию), `двусторонняя`, `переворот` (`короткий` / `длинный` — если оборот выходит вверх ногами). Новые шаблоны просто кладите в папку (лучше `.xlsx`). `POST /api/work-agents/print` — тот же запрос без чата.

## ИИ через cloud.ru

1. В личном кабинете cloud.ru: Пользователи → Сервисные аккаунты → аккаунт → «Создать API-ключ»,
   сервис — **Foundation Models**. Сохраните Key Secret — второй раз его не покажут.
2. На сайте: шестерёнка → вкладка **«ИИ · cloud.ru»** → вставьте ключ → «Проверить».
   Подтянется список моделей, доступных по ключу.
3. Выберите модель, при желании — температуру, длину ответа, память чата и характер. «Сохранить».
4. «Проверить ответ» — короткий пробный запрос к модели.
5. «Модель для смысловых связей» — эмбеддинги для «Мозгов»: выберите из списка модель с `embed` или `bge` в названии
   (например, `BAAI/bge-m3`). Если выбранной модели нет у cloud.ru и он отвечает 404 на `/embeddings`, программа сама проверяет
   список по ключу и берёт доступную модель эмбеддингов (в журнале: «Беру …»), вектора каждой модели хранятся отдельно.
   Если подходящих моделей у ключа нет, связи отключаются с понятным сообщением, остальное работает.

**Память ИИ.** Устроена как у человека — долговременная и краткосрочная.

- *Долговременная* — факты о вас с категорией (о себе, люди, работа, здоровье, предпочтения, планы, даты, другое)
  и важностью 1–5. После каждого ответа ИИ в фоне решает: добавить новый факт, **заменить** старый,
  если вы что-то уточнили или изменилось («переехал в Москву» заменяет «живёт во Владивостоке»),
  или удалить («забудь про…»). Почти одинаковые факты не дублируются.
- *Умный выбор:* в ответ идут не все факты, а важные (4–5) и 12 самых близких по смыслу к вопросу —
  ИИ не путается, даже когда фактов сотни (нужна модель эмбеддингов).
- Фраза **«это важно»** сохраняет сведения с высшим приоритетом. Фразы **«это правило»** и
  **«запомни как правило»** создают постоянное правило хозяина; установить или отменить его может только хозяин.
- *Краткосрочная* — сводка: сообщения, вышедшие за «память чата», сжимаются в пересказ,
  и ИИ не теряет нить длинного разговора. И рабочая память: тема разговора, что уже решили,
  какие вопросы открыты.

**Понимание: кто, что, для кого, зачем, почему.** ИИ хранит не просто фразы, а понимает связи:

- у факта есть *смысл* по полям: кто, что, для кого, зачем, почему, когда;
- *сущности* — люди, питомцы, места, организации, проекты, цели, события, вещи (у людей — другие имена:
  «Мама», «мамуля»); *связи* между ними с подписью («Мама → любит → зелёный чай»);
- *цели* отдельно от причин и шагов: у цели есть «почему» и статус, цепочки причин —
  связи «потому что» / «чтобы» («Выучить японский → потому что → поездка → потому что → мечта»);
- *задачи привязываются к целям*: ИИ делает это сам по разговору, вручную — в правке задачи (поле «Цель»),
  всё сразу — кнопка «🎯 К целям» внизу задач;
- в ответах ИИ опирается на понимание («что подарить маме?» → вспомнит, что она любит, и когда день рождения),
  а если неясно, для кого или зачем, — один раз уточнит.

В «Мозгах»: раскладка **«Понимание»** — в центре «Я», вокруг цели, у целей шаги-задачи, дальше люди и места,
связи подписаны, причинные — пунктиром. **Карточка сущности** — связи, факты, задачи, заметки, упоминания в чате;
у цели — «Цель достигнута ✓». **Путь «почему»** — у задачи светится цепочка до цели и её причин.
**Поиск по связям** — «мама» найдёт всё, что связано с мамой.

В настройках ИИ: факты по категориям, важность — клик по точкам, категория — выпадающий список,
блок «Сейчас в разговоре» с пересказом ранней части чата. В «Мозгах» факты сгруппированы по категориям
(важные — крупнее), рабочая память мерцает на орбите «Сейчас» вокруг ядра.

Ключ хранится только в `config.json` на этом компьютере (файл не попадает в git) и на страницу целиком не отдаётся.
Адрес API (по умолчанию `https://foundation-models.api.cloud.ru/v1`) можно поменять в «Дополнительно» —
подойдёт любой OpenAI-совместимый сервис.

## Мозги

Меню в шапке: «Главная» и «Мозги». Мозги — всё, что знает Mizuyori, в виде живого графа:
в центре ядро, вокруг разделы (Задачи, Заметки, Чат или списки задач), в них группы и точки.

- **Раскладки:** кольца (медленно вращаются), круг, соты, сила (пружины),
  плата (разделы — микросхемы, к ним от ядра идут дорожки) и HUD (кольца-дорожки, шкала, луч радара).
- **Память ИИ:** раздел с фактами, которые ИИ запомнил о вас (ромбики). Клик по факту → «Забыть этот факт».
- **Смысловые связи:** похожие по смыслу задачи, заметки и факты соединены линиями.
  Считаются эмбеддингами cloud.ru (модель выбирается в настройках ИИ), хранятся в базе —
  пересчитываются только изменённые тексты. Порог похожести — ползунок на панели.
  В карточке точки — список «Похожее по смыслу».
- **Значки:** люди, цели, места и проекты (раздел «Понимание») — кружки с символом: в кольцах — на внешнем
  кольце, в сотах — в щелях между шестиугольниками. Вокруг ядра — зубчатое кольцо, под ядром — имя.
- **Агенты на графе:** внешнее кольцо «Агенты» — значки агентов со звёздами уровня. От каждого тянутся нити
  к разделам, с которыми он работает (Память → Память ИИ и Понимание, Собеседник → Чат и «Сейчас»…).
  Пока агент работает, значок светится, по нитям бегут огоньки, раздел отзывается кольцом.
  Наведение — что делает и последний результат, клик — окно агента. Выключается флажком «Агенты на графе».
- **Блоки-матрицы:** группы в кольцах — ровные блоки точек, пустые места — тусклые точки.
- **Наведение на раздел:** остальное гаснет, к точкам раздела бегут огоньки, в подсказке — группы и их размер.
- **Вид:** «Разделы» или «Списки» (каждый список задач — свой раздел, внутри — по срокам).
- **Мышь:** тянуть — двигать, колесо — приближать, наведение на раздел — связи к его точкам.
  Клик по разделу — выделить, двойной клик — свернуть. Клик по точке — карточка с кнопкой «Открыть».
- **Поиск:** клавиша `/`, Enter — к первой найденной точке, Esc — сбросить.
- **Панель:** ползунки вращения, пружин и размера; «Развернуть / Свернуть всё», «В центр»,
  «Сохранить настройки» (в `config.json`), «Скачать PNG».

**Мозги → Список:** поиск ищет и по знаниям **всех** агентов (правила, приёмы, частые ошибки), клик по найденному открывает агента.
Сверху — **фильтры** (работают сейчас, с ошибками, без знаний, давно не учились), **сортировка** (по группам, активности,
уровню, давно не учились, ошибкам, знаниям, алфавиту) и **период графиков** 7 / 30 / 90 дней. У каждого знания агента — кнопки:
«В правило», «В приём» (для ошибки), «Передать…» коллеге (уходит приёмом «от <автор>» и «Уроком» на доске) и «Удалить»;
записей больше 12 — «Показать все».
Кнопка «Проверить знания» показывает **повторы** и **возможные противоречия** между знаниями агентов (одна тема, одна запись
запрещает, другая велит); любую запись можно удалить на месте. Это подсказки, решаете вы. Код: `agents.проверить_знания()`.

### Душа

Вкладка «♡ Душа» рядом с «Граф». В центре светящееся ядро: дышит в такт энергии,
цвет — от настроения. Вокруг по орбитам летают черты, ценности и границы.

- **Суть, черты, ценности, границы, манера речи** — кнопка «Изменить», фишки добавляются Enter-ом
  (до 8 в каждом разделе), «Вернуть исходную душу» — к начальным.
- **Настроение** считается из ваших дел и разговоров: всё на сегодня сделано — радуется,
  только что говорили — воодушевлена, 3 и больше просрочек — беспокоится, давно не говорили — скучает.
  Причины показаны в карточке.
- **Мы знакомы:** дни, сообщения, факты, сколько всего в понимании.
- **Нити к важному:** от ядра тянутся нити к активным целям (🎯 с кольцом прогресса), проектам (📁) и людям (👤),
  по нитям бегут огоньки; чем важнее — тем ярче. Наведение — её мнение об этом, клик — карточка мнения.
- **Мнения:** что она честно думает о ваших целях и проектах (радуюсь, верю, сомневаюсь, беспокоюсь) и почему.
  Обновляются сами раз в день после разговора или кнопкой «Обновить»; лишнее — крестиком.
- **Мысли:** перед ответом ИИ коротко думает про себя. В чате над ответом значок «💭 мысль» —
  клик раскрывает, о чём она подумала. Выключается в карточке «Мысли».
- **Фоновое развитие:** после часа бездействия Душа осмысливает память, цели и незавершённые дела
  (не чаще раза в 12 часов), сохраняет полезный вывод и привычку для будущих ответов, а идеи изменения
  программы оставляет хозяину как предложение. Функцию можно выключить в карточке «Фоновое развитие».
- **Итоги месяцев:** 20 последних выводов хранятся целиком, а старые не пропадают: сворачиваются в «главное за месяц»
  (сколько выводов, до трёх главных, до трёх привычек; хранится 24 месяца, работает без ИИ). В «Пути роста» они — «Итог месяца»,
  два последних месяца добавляются к подсказке ИИ.
- **Работа в Душе:** срочное из «Работы» (просрочены ОСАГО, техосмотр, ТО, шины, договоры, оплаты — те же наблюдения, что у
  Механика и Юриста) попадает в подсказку ИИ и в данные фонового развития.
- **Иерархия решений:** воля хозяина → его постоянные правила → активные цели → текущее поручение.
  При конфликте Душа уточняет приоритет; если видит ошибку или существенный риск, честно возражает,
  объясняет причину и предлагает способ лучше выполнить намерение хозяина.
- **Переход:** при переключении граф сворачивается в ядро, из ядра раскрывается душа, и обратно.
- Душа, настроение и мнения добавляются к каждому ответу ИИ. Хранятся в базе.

Настройки проекта — значок шестерёнки в левом верхнем углу сайта.

### Что происходит при первом запуске

Анализ движения ГСМ: км и остаток на начало подставляются из конца прошлого месяца сами и обновляются, если цифры прошлого месяца поменялись; вписанное руками не перезаписывается. Топливо по карте, закреплённой за несколькими машинами, в итог входит один раз; заправки по картам без машины показаны отдельным предупреждением.

Карта и водитель: топливная карта закреплена за сотрудником, а топливо и остаток в баке принадлежат машине. Заправки по карте идут на ту машину, на которой сотрудник ездил в день заправки (история «Водители машины» в карточке автомобиля, дату пересадки можно поправить, можно добавить прошлый период). Пересел на другую машину — остаток на старой сохраняется и переносится в следующий месяц, на новой считается её собственный.

Статистика и контроль ГСМ: признаки считает `mizuyori/gsm_stats.py`, оформление — `static/gsm-stats.js`. Для проверки «заправка больше бака» укажите «Объём бака» в карточке автомобиля. В выборе периода зелёным подсвечены месяцы, за которые загружена выписка.

## История ремонтов по машинам

Когда смета в чате подтверждена, она записывается в историю машины (по госномеру или марке/модели из сметы). В карточке автомобиля — блок «Ремонты и замены». В чате спросите «что ремонтировали на Прадо» (ответит механик) или «сколько потратили на ремонт Прадо» (ответит экономист).

## Новые агенты и их вид

Добавлено десять агентов «Работы»: Снабженец, Архивариус, Менеджер по контрагентам, Проверяющий, Секретарь, Контролёр сроков, Охрана труда, ГСМ-контролёр, Склад и запчасти, Бухгалтер. У каждого свои наблюдения за данными, своя память, обмен записками, ежедневная учёба и обращение в чате («Бухгалтер, что с оплатами?»). На главной агенты стоят плитками по пять в ряд, ряды идут вниз, цвет плитки — цвет группы; в «Мозгах» кольцо агентов растёт по числу агентов, группы выделены цветными дугами и подписями.

## Архив и контрагенты («Работа → Архив и контрагенты»)

Папки как на Яндекс.Диске: **Контрагент → Договор → раздел → файл**. Разделы: «Закупка (согласование)», «Договор», «Счета и акты», «Переписка», «Прочее». Файлы лежат в `data/архив/…`, в базе — индекс (вид, номер, дата, сумма, описание, текст) для поиска и для агентов.

- **База контрагентов** — вручную: «+ Контрагент» (название, ИНН, КПП, адрес, телефон, почта, контакт, банк). Договоры привязываются к контрагенту по ИНН или названию.
- **Загрузка файлов** (кнопкой или перетаскиванием): сайт определяет вид документа, номер, дату, сумму и контрагента (по признакам, с ИИ — точнее), кладёт файл в нужную папку и переименовывает в `Дата_Вид_Контрагент_№_Сумма.расширение`. Файлы без известного контрагента — во «Входящих», после заведения карточки они раскладываются сами. Повторный файл не загружается.
- **Комплект закупки** договора: смета или КП, служебная записка, договор или счёт-оферта, дефектовая ведомость (для ремонтов) и всё, что приложили вручную. У договора есть статус закупки.
- **Смета из чата:** после подтверждения сама смета и три черновика агентов попадают в архив — в папку договора контрагента-исполнителя.
- **Агенты знают, где что лежит:** в чате спросите «где лежит договор с АвтоСервис», «чего не хватает для согласования» — ответят архивариус, снабженец или менеджер по контрагентам; они же замечают входящие, комплекты без документов и карточки без ИНН.

## Главная: вид агентов и эффекты работы

Плитки агентов окрашены в цвет группы, у каждой — звёзды уровня и мини-график недели. Работающий агент: вращающаяся светящаяся кромка, волны и спутники вокруг кружка. Когда агент закончил, над плиткой всплывает пузырь с результатом («✓ замечаний: 1»); при повышении уровня — золотая вспышка. Передача работы и записки показываются летящими искрами и конвертами цвета отправителя; в шапке бегут столбики «пульса». При включённом «уменьшении движения» в системе анимации отключаются.

## Обмен между агентами

Кнопка «Обмен» в шапке агентов на главной открывает ленту: кто кому передал **работу** (замечания и поручения), **знание** (урок, который агент посоветовал коллеге; видно, рассмотрел ли его получатель) и **опыт** (приём, который коллега принял в свою память). Сверху — кто кому передаёт чаще всего. Лента обновляется сама. Звёздочки уровня на плитках убраны (уровень виден во всплывающей подсказке).

### Посылки между агентами (главная)

Между плитками агентов летят три вида посылок: **конверт** с цветной отметкой отправителя (передача работы), **светящаяся лампочка** с лучами (урок / знание) и **золотая вращающаяся звезда** (принятый опыт). По прилёте плитка «подпрыгивает», знание и опыт впитываются в неё частицами, появляется пузырь «💡 от <Имя>». Полный список — в окне «Обмен».

### Смотрящий (агент-распределитель)

Читает чат и раздаёт задания другим агентам. Пример: «сделай служебку на выходные в Кихтев, суббота 14» → Смотрящий понимает дату и объект, спрашивает недостающее (кого отметить), показывает план и после «да» делает: Старший инженер пишет черновик служебной записки, Кадровик ставит «работу в выходной» в табель, Контролёр сроков заводит напоминание в «Делах». Ответ «отмена» снимает задание. Задания и отчёты идут через доску, поэтому между плитками летят конверты. Работает без ИИ, по правилам (`overseer.py`).

### Чувства агентов

- **Руки.** Смотрящий умеет ещё и «поставь Иванова в отпуск с 16 по 20 ноября» (табель по будням, коды ОТ/Б/К) и «добавь задачу …» (в «Дела»), всегда после «да».
- **Глаза.** Файл, прикреплённый в чат: если это не смета, а договор, счёт, акт и т. п. — Архивариус опознаёт его и кладёт в архив.
- **Уши.** Папка `data/Приёмная`: всё, что туда бросить, Архивариус сам разложит по контрагентам и договорам (проверка раз в 20 секунд), обработанное уходит в `обработано`.
- **Ноги.** «Найди цену масла 5W30» — агент ходит в интернет (поиск DuckDuckGo) и приносит ссылки. Нужен выход в сеть с вашего компьютера.

Смотрящий добирает ИИ-разбором то, что не поняли правила: «Смотрящий, Иванов заболел на следующую неделю» → больничный на нужные даты (нужен подключённый ИИ; без него работают только ключевые слова).

Агенты учатся на ваших правках: если вы изменили отметку табеля, которую поставил Кадровик, или переписали/удалили служебную записку Старшего инженера, агент записывает это как ошибку, а ИИ-размышление (при подключённом ИИ) превращает правки в правила.

«Мозги → Список»: вкладка рядом с «Граф» и «Душа» — все агенты по группам с уровнем, умениями (🖐👁👂🦶), числом знаний; клик раскрывает правила, приёмы и частые ошибки агента, есть поиск.

«Мозги → Душа» стала аккуратнее: орбиты и карточки черт, ценностей и границ имеют свои цвета (синий, зелёный, оранжевый), подписи на орбитах сокращаются и раскрываются при наведении, у карточек векторные значки и счётчики, энергия показана кольцом, у мнений — значки тона и сводка по тонам.

«Мозги → Душа»: вместо орбит — звёздное небо. Черты, ценности и границы — созвездия (синее, зелёное, оранжевое). Вокруг ядра идёт кольцо-график фонового обучения за 14 дней (размышления Души, приёмы агентов, поправки), к ядру время от времени летят кометы — новые выводы. Справа карточка «Как она учится» со статусом фона, плитками и столбиками по дням.

Детализация «Мозгов»: в графе у агентов кольцо уровня и бейдж с номером, подсказка показывает опыт, график недели, знания и умения, названия групп стоят внутри кольца и не налезают на подписи. В «Душе» небо стало многослойным: туманности, Млечный Путь, три слоя звёзд с параллаксом, спиральные рукава у ядра, падающие звёзды, названия созвездий, лучи у ярких звёзд и подсветка наведённой звезды.

«Мозги → Душа → Путь роста»: список того, как душа развивалась и росла: выводы, привычки, предложения, правила, приёмы и поправки хозяина по дням с фильтрами, уровень души с шкалой опыта.

### Панель «Граф»
Панель управления графа переоформлена: плитки раскладок с векторными значками, переключатели вместо флажков, ползунки с подсвеченной дорожкой и значком значения, цветной статус смысловых связей, кнопки с волной от клика. Учитывает тему и `prefers-reduced-motion`.

### Автоматика
- Если выбранной модели эмбеддингов нет у ключа (404), найденная замена сразу сохраняется в настройках ИИ.
- `Mizuyori.bat` при запуске делает `git pull --ff-only`, если папка — клон git (без конфликтов; отключить: переменная `MIZUYORI_NO_UPDATE=1`).

### Дела
Экран «Дела» переоформлен: значки вместо эмодзи во вкладках видов и разделов, дата в шапке, карточка добавления задачи с подсветкой при вводе, цветная отметка приоритета, карточки групп с эффектом при наведении, оформленное пустое состояние.

### Обмен между агентами
Окно «Обмен» переоформлено: плитки-счётчики по типам (Работа, Знание, Опыт) со значками вместо эмодзи, карточки событий с цветной меткой типа, индикатор «ждёт получателя», оформленное пустое состояние.

### Роль агента
В карточке агента появилась вкладка «Роль»: роль, цель, предыстория и дополнительные указания. Эти строки добавляются к заданию ИИ перед правилами и приёмами агента; формат ответов не меняется. Поле пустое — агент работает как раньше.

### Поручения агентам
На главной рядом с «Обмен» и «Доска» появилась кнопка «Поручения». Поручение — цепочка шагов: у каждого есть исполнитель, описание, «что считать готовым», необязательный инструмент и галочка «ждать моего подтверждения».
- Проверяющий сверяет результат с ожиданием; не подошло — одна повторная попытка с замечанием, потом поручение ждёт вашего решения («Принять как есть» или «Отклонить»).
- Шаблоны с `{параметрами}`: «Закупка запчасти на {техника}» — значения вводятся при запуске. Готовых шаблонов восемь: закупка запчасти, готовность парка к выпуску, проверка путевых листов за месяц, контроль расхода ГСМ, документы на технику, подготовка к техосмотру, договор поставки, недельная сводка для главного механика. Новые готовые шаблоны добавляются сами при обновлении (по названию); удалённый вами не возвращается.
- «Руководитель»: Стратег сам делит цель на шаги, назначает агентов и принимает итог (нужен ИИ).
- На каждом шаге записываются секунды, запросы к ИИ и токены.
- Новые навыки подключаются в `mizuyori/tools.py` одной функцией с декоратором `@инструмент(...)`; «рискованный» инструмент всегда ждёт подтверждения.

### Поиск через настоящий Chrome (против капчи)
По умолчанию поиск идёт обычными запросами и иногда упирается в капчу. В `settings.json` (раздел `агенты`) можно задать `"браузер_для_поиска"`:
- `"chrome"` — Mizuyori сам запускает установленный Chrome с отдельным профилем в `data/браузер`;
- `"http://127.0.0.1:9222"` — подключиться к уже запущенному Chrome (`chrome --remote-debugging-port=9222 --user-data-dir=<своя папка>`; Chrome 136+ не открывает отладочный порт на профиле по умолчанию).

Нужен пакет: `pip install playwright` (скачивать браузер не нужно). Если Chrome не запустился, поиск сам возвращается к обычному способу на 10 минут.

### Версии, навыки и журнал аудита
- **Версии и откат.** Любое изменение роли, правил, приёмов и навыков агента запоминается; во вкладке «Роль» внизу список версий (`v1`, `v2`…) и кнопка «Вернуть». Сам откат тоже записывается как версия, так что его можно отменить. Хранится до 40 версий на агента.
- **Навыки.** Вкладка «Навыки» в карточке агента: короткая инструкция + слова «когда подключать». К заданию ИИ навык добавляется только если запрос подходит по словам (до трёх за раз); навык без слов подключается всегда.
- **Журнал аудита.** Вкладка «Журнал» в окне «Поручения»: кто, когда и что подтвердил, отклонил или изменил (поручения, шаблоны, роли, правила, навыки, откаты). Хранятся последние 2000 записей.

### Самоулучшение агентов (evolve)
- Каждый шаг поручения получает оценку (1 — с первого раза, 0.6 — со второго, 0.3 — принят вручную, 0 — отклонён/ошибка), секунды и токены; график — вкладка «Улучшения» в карточке агента.
- Новый приём из фоновой учёбы проверяется на прошлых случаях агента; если хуже — не записывается, а попадает в «Улучшения» как не прошедший проверку.
- Раз в сутки агент с оценкой ниже 70% (минимум 5 шагов за 14 дней) разбирает неудачи и предлагает одну правку (правило / дополнение к роли / навык). Применяется только после «Принять»; откат — вкладка «Роль».

### Файрвол инструментов и шкала поручения
- Перед вызовом инструмента проверяется, что агенту он положен («поиск» — закупщикам 🦶, «замечания» — агентам-наблюдателям) и что задание не пустое/не слишком длинное/без управляющих символов. Проверка при создании, при запуске шага и в планировщике; блокировки пишутся в журнал.
- Подтверждение привязано к конкретному вызову (отпечаток агент+инструмент+описание): изменённый шаг снова спросит, чужой отпечаток отвергается.
- В карточке поручения — временная шкала: работа, ожидание вас, повторные попытки по каждому шагу.

### Тест качества поиска
Окно «Поручения» → «Поиск» → «Проверить поиск»: 12 типовых запросов («фильтр VIC C-111», «шины 265/65 R17»…) идут через поиск снабженца; ожидаемое в топ-3 — 1 балл, в топ-8 — 0.5. Результат сравнивается с прошлым прогоном (хуже/лучше/без изменений); набор — `mizuyori/search_eval.py`.

### Память: гибридный поиск, архив, предложения, «сон»
- Поиск фактов склеивает три канала: смысл (эмбеддинги), слова (BM25; артикул «C-111» находится и как «C111») и сущности из вопроса. «Сейчас» поднимает свежие факты, «раньше» добавляет устаревшие (с пометкой), «планирую» — факты на будущее.
- Ничего не стирается по решению ИИ: забытое уходит в архив (вернуть можно), у факта есть история правок. Настройки ИИ → «Порядок в памяти».
- Переключатель «Спрашивать перед запоминанием»: новые факты ждут вашего «Запомнить».
- Раз в сутки «сон»: слияние дублей, архив давно ненужного и неважного, предложения-обобщения. Важное (важность 4–5, работа, даты, ТО, сроки, документы) не забывается.

### Наборы инструментов и передача шага
- Окно «Поручения» → «Инструменты»: режим «только чтение» (блокирует инструменты, меняющие данные) и включение/выключение наборов («интернет», «данные»…). Через API можно ограничить набор для конкретного агента (`PUT /api/tools/settings`, поле `агенты`). Блокировки попадают в журнал.
- Передача шага (handoff): агент может ответить «ПЕРЕДАЮ: юрист: причина» — шаг перейдёт коллеге (до двух передач). Передача отклоняется, если такого агента нет или ему нельзя пользоваться инструментом шага. Оценка и цепочка «Снабженец → Юрист» видны в карточке и шкале.

### Чтение страницы по структуре и MCP-серверы
- Инструмент «страница»: читает страницу как структуру (заголовки, списки, цены, ссылки, кнопки), без скриншотов. С включённым браузером для поиска — дерево доступности настоящего Chrome, без него — текст из обычного скачивания. Можно добавить слова: вернутся только подходящие строки. Локальные и внутренние адреса закрыты.
- Окно «Поручения» → «Инструменты» → «Внешние MCP-серверы»: включаются стандартные Fetch и Time (нужна программа `uv`); их инструменты («fetch.fetch», «time.get_current_time») появляются в реестре в наборе «внешние» и подчиняются тому же файрволу. Каталог закрытый: произвольные команды из интерфейса не запускаются.

### Очередь запросов к ИИ
Все запросы идут через общую очередь (`ai._открыть`): не больше 4 одновременно; при 429 и сбоях сервера (500/502/503/504) — повтор с паузой (по `Retry-After`, иначе 2→6→15→30 с), а после 429 пауза действует на все потоки сразу. Приоритеты: чат важнее поручений, поручения важнее фона (учёба, сон памяти, разбор неудач): фон не стартует, пока идёт запрос чата.

### Поиск: Chrome по умолчанию, кэш, цены со страниц
- `браузер_для_поиска` теперь «авто»: если на компьютере есть Chrome и пакет playwright, поиск идёт через свой Chrome с профилем (капчи почти нет); иначе тихо обычный поиск. «выкл» — всегда обычный.
- Непустая выдача кэшируется на 6 часов (база, таблица `поиск_кэш`): повторы не провоцируют капчу. Тест качества поиска идёт без кэша.
- У магазинов запчастей без цены в выдаче Mizuyori читает страницу (по структуре) и достаёт цену: рядом с артикулом — точно, иначе помечает «по странице, проверьте». Цены тоже кэшируются.

### Расход токенов и автооткат улучшений
- Окно «Поручения» → «Расход»: токены за 14 дней по агентам, по дням и по приоритетам (чат, поручения, фон), очередь запросов. Расход пишется на агента, который в этот момент «в работе», иначе на «чат». Потоковый чат считается прикидкой по длине.
- Автооткат: после принятого улучшения Mizuyori сравнивает оценки агента «до» и «после» (минимум 5 шагов). Упала больше чем на 15 пунктов — в «Улучшениях» появляется предложение откатить версию (кнопки «Откатить» и «Оставить»).

## Регион и уборка

В `settings.json`, раздел `агенты`:
- `регион`, `главный_город` — приоритетный регион закупок (по умолчанию Приморский край, Владивосток): добавляются к запросам, попадают в подсказки ИИ и в шапку договора.
- `признаки_региона` — слова, по которым местное предложение узнаётся в тексте; `метки_ссылок_региона` — то же для адресов сайтов.
- `хранить_дней` (30–3650, по умолчанию 180) — раз в сутки убираются старые записи аудита, истории и оценок агентов, расхода, прогонов проверки поиска, прочитанных записок на доске, версий фактов памяти и старые файлы в `logs/`. Сами факты памяти, заметки, задачи и поручения не трогаются. Кэш поиска живёт неделю.

## Профили агентов

У каждого из 25 агентов при первом запуске заполняются «Роль», «Цель», «Предыстория» и «Дополнительные указания» (`mizuyori/agent_profiles.py`). Заполняются только пустые профили: всё, что вы написали сами, остаётся. Править можно в карточке агента.

## Просьбы из чата → настоящие поручения

Раньше чат мог написать «передала снабженцу», хотя ничего не запускалось. Теперь:
- **Чат ничего не обещает сам.** Если ответ содержит «передала / запущу / сообщу, как ответит», а запуска не было, к ответу добавляется предупреждение, что это только слова.
- **Передача (`mizuyori/chat_delegate.py`).** Если сообщение похоже на просьбу («пускай юрист сверит сроки договоров», «проверь …», «надо узнать …»), ИИ определяет исполнителя, инструмент и ожидаемый результат и создаёт обычное поручение: шаги, проверка результата, оценка, запись в аудит. Разговорные реплики на это не тратят запрос к ИИ.
- **Подтверждение.** Режим в `settings.json` → `агенты` → `поручения_из_чата`: `авто` (по умолчанию: безопасное запускается сразу, рискованное инструмент или внешний MCP — после «да / нет»), `всегда_спрашивать` (всегда «Понял так: … Запускаю? да / нет»), `выкл`.
- **Итог в чат.** Когда поручение остановилось, в чат само приходит сообщение: что сделал агент, или почему не вышло, или вопрос «Разрешаете? да / нет» (ответ «да» продолжает, «нет» останавливает). Окно чата подтягивает такие сообщения каждые несколько секунд.

## Главный экран: «Ждёт вас» и «Сегодня»

Над чатом две строки. **Ждёт вас**: поручения, которым нужно ваше решение, предложения агентов и предложения по памяти; нажмите, чтобы открыть. **Сегодня**: сколько срочных замечаний и сколько «внимание» нашли агенты по данным (сроки, ТО, ГСМ…); по клику раскрывается список, а клик по замечанию открывает агента. Данные идут из `GET /api/today`.

В панели агентов по умолчанию видны только те, кто работает, ошибся, прислал записку или имеет замечания (с числом на плитке); остальные скрыты, кнопка «все» у группы показывает всех. Окно «Поручения» разделено на «Работу» (поручения, новое, шаблоны, журнал) и «Настройки агентов» (инструменты, расход, поиск). Мелкий текст стал крупнее, приглушённый серый контрастнее, часы подгоняются под ширину колонки.

## Знания агентов о вашей работе

Три вещи, которые делают агентов точнее (модуль `knowledge.py`, миграция 30 в базе).

- **Личные факты агента.** В карточке агента («Память» → «Что знаю о вашей работе») можно записать то, что знает только он: «для Hilux берём фильтры VIC, цену сверяем с Автодоктором». В задание ИИ попадают до пяти фактов: сначала подходящие к запросу, потом самые свежие. Факт одного агента другим не виден.
- **Общий справочник техники и контрагентов.** «Поручения агентам» → «Настройки агентов» → «Справочник». Автомобили и контрагентов из раздела «Работа» агенты знают сами. Здесь добавляются другие названия («хайлюкс, белый пикап») и пометки («возит бригаду»). Если просьба называет машину (название, госномер в любой записи вроде «а 123 вс»), контрагента (название, ИНН) или алиас, любой агент получает короткую справку и пишет теми же словами. Короткие названия (до двух знаков) не срабатывают, чтобы не цеплять чужие слова. API: `GET/POST/PUT/DELETE /api/reference-book`.
- **Обучение на ваших правках.** В поручении у результата шага есть кнопка «Исправить результат». Следующие шаги и итог берут ваш вариант. Агент записывает в частые ошибки, что вы добавили и убрали, сохраняет себе факт «из правки», а фоновая учёба получает событие «правка» с текстом до и после и сама формулирует приём (с проверкой на прошлом опыте). Правки видны в карточке агента. Пока поручение выполняется, править нельзя. API: `PUT /api/missions/{id}/steps/{шаг}/result`.

## Герои агентов

У каждого из 26 агентов свой оригинальный персонаж, нарисованный вектором (`static/characters.js`): поэтому он одинаково чёткий на ноутбуке и в 4K. Герой собран из слоёв: аура, тень, одна из шести форм тела, одна из пяти форм головы, экран-лицо с глазами (овалы, круги, полосы или один большой глаз), руки и реквизит по профессии (каска и чертёж у инженера, весы у юриста, штамп у делопроизводителя, песочные часы у контролёра сроков, тележка у снабженца, калькулятор у бухгалтера и так далее). Цвет у каждого свой. Новому агенту без своей записи в таблице `ГЕРОИ` достаётся стандартный герой.

Герои живут: дышат, поворачивают голову, моргают и следят глазами за курсором, плитка под курсором наклоняется. Когда агент **работает**, глаза превращаются в бегущий луч, руки стучат, реквизит ускоряется, по рамке бежит комета цвета группы, вверх поднимаются искры, вокруг расходятся волны. **Спит** (сегодня ничего не делал): глаза закрыты, плывут «z». **Ошибка:** глаза-крестики и красное свечение. При успехе герой подпрыгивает, при провале дрожит. Панель агентов подсвечена северным сиянием, у каждой плитки светящийся пол с сеткой. При включённом «уменьшении движения» в системе анимации отключаются.

Плакат всей команды в разрешении 3840×2160 лежит в `docs/agents-4k.png`.

## Кабинеты

Агентов теперь 49, и они разложены по четырём кабинетам (вкладки над плитками на главной; кнопка «Схема» открывает схему подчинения):

- **Бухгалтерия** — главный бухгалтер, заместитель, сектор ОС и транспорта, материальный сектор (ГСМ и путевые, запчасти), расчёты с персоналом (зарплата водителей и АУП с ремзоной), расчёты с контрагентами (реализация, поставщики, подотчёт), налоговая группа, касса и документы.
- **Главный механик** — техслужба (старший инженер, механик по выпуску, диспетчер, трассировщик), ремзона (мастер, дефектовщик, шины и АКБ), снабжение со складом, безопасность и сроки.
- **Экономисты** — главный экономист, аналитик KPI, плановик, экономисты по себестоимости, закупкам и стоимости владения парком.
- **Штаб** — ядро ИИ (собеседник, память, смысл, летописец, стратег, душа) и общие помощники (смотрящий, секретарь, юрист, кадровик, менеджер по контрагентам).

Двойной работы нет: уже существовавшие агенты, закрывавшие роль из схемы, переехали в кабинеты и получили новые названия (бухгалтер → «Бухгалтер по поставщикам», ГСМ-контролёр → «Бухгалтер по ГСМ и путевым», экономист → «Главный экономист»). Их история и опыт сохранены.

Наблюдают данные только те, у кого они есть на сайте (табель, путевые, ремонты, договоры, карточки машин, налоговые сроки). Реализация, кассир и старший кассир работают как «ролевые»: своих замечаний не выдумывают, а помогают в чате и по поручениям. Структура и роли описаны в `mizuyori/cabinets.py`, герои — в `static/characters.js`.
